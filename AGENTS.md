# AGENTS.md — правила работы в репозитории

Этот файл — для людей и AI-агентов, которые работают с кодом. Здесь только
правила. Архитектура — в `docs/ARCHITECTURE.md`, контракты модулей — в
`docs/specs/`.

## Документация

Документы в порядке убывания приоритета:

1. Хаб `cybercity/` — системные документы (состав, конвенции, ADR).
2. `AGENTS.md` (этот файл) — правила работы.
3. `docs/ARCHITECTURE.md` — архитектура системы.
4. `docs/specs/*.md` — контракты crate'ов.
5. Код — реализация.

Если документы противоречат друг другу — побеждает старший. Расхождение —
повод для ADR в хабе.

## Модель ветвления

```
main ← merge только из dev
dev  ← PR из feature-веток
feat/<задача> ← от dev, удаляется после merge
```

- `main` — стабильная. Вливается только из `dev`.
- `dev` — разработческая. Вливается из feature-веток через PR.
- Прямой коммит в `main` или `dev` — запрещён. Только через feature-ветку + PR.

## Рабочий цикл

1. Прочитать `docs/BACKLOG.md` — взять первый невыполненный пункт.
2. Прочитать `docs/INDEX.md` → `docs/ARCHITECTURE.md` → спек нужного crate'а.
3. Создать ветку от dev: `git checkout dev && git pull && git checkout -b feat/<задача>`.
4. Изменить код. Написать тесты по пунктам «Что есть» в спеке.
5. Запустить `./scripts/verify.sh`. Если fail — чинить, повторить.
6. Обновить спек: перенести реализованное из «Что TODO» в «Что есть».
7. Обновить BACKLOG: поставить `[x]` на выполненный пункт.
8. Закоммитить (Conventional Commits, см. ниже).
9. Запушить, открыть PR в `dev`.
10. После merge — ветка удаляется.

## Что можно

- Писать код в `crates/`.
- Менять `Cargo.toml` с обоснованием.
- Обновлять `docs/`, `README.md`, `AGENTS.md`.
- Создавать feature-ветки, коммитить, пушить, открывать PR в `dev`.
- Обновлять спеки после реализации.

## Что нельзя

- Коммитить напрямую в `main` или `dev`.
- Создавать ADR в этом репозитории. Все ADR — в хабе `cybercity/adr/`.
- Менять ADR хаба без явного указания.
- Добавлять зависимости без обоснования.
- Выдавать stub за реальную реализацию. Честно помечать: что placeholder,
  что TODO.
- Трогать `Cargo.lock`, `config/`, `target/`, `.gitignore` без
  одобрения.

## Коммиты

Conventional Commits. Summary — английский, тело — русский.

```
feat: add zfs-snapshot fs probe
fix: reject path traversal in HostBridge
docs: update ARCHITECTURE.md with probe matrix
refactor: extract envelope signing into SecureTransport
```

Breaking changes — `BREAKING CHANGE:` в теле.

## ADR

Архитектурные решения живут в хабе `cybercity/adr/`, не здесь. Если изменение
затрагивает архитектуру — написать ADR в хабе, сослаться на него из
`docs/ARCHITECTURE.md`. Старые ADR помечать `Superseded`, не удалять.

## Язык

Документация — русский. Английский допустим только для: идентификаторов кода,
имён crate'ов, значений `Status:` в ADR, summary-строки коммита.
